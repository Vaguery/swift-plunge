# What this project is

**PropellerWithStructs** is a Swift implementation of **Push**, a stack-based programming language purpose-built for **genetic programming (GP)** — evolving computer programs via variation and selection rather than writing them by hand. The name is a tell: it's a reimplementation of Lee Spector's Clojure system **[Propeller](https://github.com/lspector/propeller)** (the code even cites Propeller's source for the interpreter's numeric limits), rebuilt in Swift using `struct`s (value types) instead of classes — hence "WithStructs." Given the file lineage cross-referencing Clojush and Klapaucius (two other Push dialects), and that William Tozier is a known GP researcher, this reads as a from-scratch, type-safe, native port of an established research language rather than a novel design.

## The `Push` language

Push programs operate on a **bank of typed stacks** rather than variables — `bool`, `int`, `double`, `char`, `string`, `exec`, `code`, plus vector variants (`vecInt`, `vecBool`, etc.) and an `error` stack (`Stacks.swift`). Every instruction:

- declares which stacks it needs (`parameters: [PushStack]`),
- pops its arguments only if *all* are present (`Behavior.isSatisfied`/`gather`, `Behavior Infrastructure.swift`),
- transforms them, and
- routes results back onto (possibly different) stacks via a `Router`.

This "pop only if fully satisfied, otherwise no-op" rule is what makes Push famously robust to random/mutated code — a malformed program segment just does nothing instead of crashing, which is essential when programs are generated by mutation and crossover rather than a human.

The key trick that makes Push evolvable is that **code is data**: a `CodeItem` holds a nested `[any Item]`, and when it reaches the front of the `exec` stack, `Interpreter.unwrapCodeItem` splices its contents back onto `exec` to execute (`Interpreter.swift:127`). This is what lets instructions like `exec_if`, `exec_do*times`, quoting, etc. treat program fragments as first-class values that can be built, stored, and rearranged — the substrate GP needs to recombine programs.

There's also a non-standard `isContingent` flag and a `crux()` method on every `Item` (`Items.swift`) that trace whether a value was produced inside a conditionally-executed code branch, and let you walk back through an item's `call` history to find the original leaf that produced it. That's not part of vanilla Push — it looks like Tozier's own extension, likely to support novel operators (the `codeFuncFrom*Crux` instructions sketched in `Notes on Push/Code instruction planning.markdown`) or provenance-based analysis of evolved programs.

## Why it's built this way

- **`Interpreter`** is the runtime: it owns the stacks, the `[PushInstruction: Behavior]` dispatch table (assembled from per-type behavior files — `Int Behaviors.swift`, `String Behaviors.swift`, etc.), and a `step()`/`run()` loop with a hard `stepLimit` — necessary because evolved programs can infinite-loop, so the interpreter must be able to forcibly bound execution.
- **`Recorder`/`AnyRecorder`** let you instrument a run — snapshot some part of interpreter state at every step — which is exactly what you need for tracing program behavior or computing fitness during evolution.
- **`Search/` (`Plushy.swift`, `Individual.swift`, `RandomCode.swift`)** is the beginning of the GP layer proper: `Plushy` converts a flat, linear genome (the "plushy" representation standard in PushGP, used because it's easy to mutate/crossover) into the nested `CodeItem` tree the interpreter actually runs; `Individual` pairs a program with its evolved constants; `RandomCode` presumably generates the initial population.
- The exhaustive per-type unit test suites (`PropellerWithStructsUnitTests/Behaviors/*`) suggest the current phase of work is building out a *complete and correct* instruction set — matching Propeller/Clojush's instruction coverage (tracked explicitly in `Notes on Push/instruction coverage.markdown`) — before layering the actual evolutionary search (selection, mutation, crossover, populations) on top.

## My read on the purpose

This is a foundational research/engineering effort to get a fast, memory-safe, native Push interpreter running correctly on Apple platforms — swapping Clojure's dynamic, class-heavy runtime for Swift's value semantics — as the substrate for a future genetic-programming system (possibly with a SwiftUI front end eventually, though `ContentView.swift` is still just the default template). It's infrastructure-first: get the language semantics bulletproof via tests, then build evolution on top.
